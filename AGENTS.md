# AGENTS.md — Music Context Sandbox

Instructions for any coding agent (Claude Code or otherwise) working in this repository.
Read this file fully before making changes. When in doubt, ask the human; do not guess.

## What this project is

An agent-first music intelligence sandbox built by one person. It turns a hand-curated
corpus of ~1,000 albums (post-punk → dream pop → shoegaze → slowcore/trip-hop corridor,
plus darkwave, coldwave, Latin American, and Asian scenes) into a recommendation API
that returns **typed, evidence-backed, provenance-labeled** results. The differentiator
is trust, not coverage: every recommendation must carry reasons with sources; the system
says "outside my corpus" instead of guessing.

## Repository layout

```
data/seed_albums.csv      # human-curated anchor list. Source of truth. Human edits.
data/descriptors.csv      # human mood/sonic/scene annotations. Human edits.

data/resolved_albums.csv  # generated by resolve. Do not hand-edit.
data/candidates.csv       # generated by expand; human marks keep/skip.

app.py                    # FastAPI platform: POST /recommendations, GET /health, GET /
plan.md                   # phased plan with gates. Follow it; update status as you go.
AGENTS.md                 # this file
```

## Hard rules (non-negotiable)

1. **Verify entities; label interpretations.** LLMs may propose candidate artists and
   albums when guided by the recommendation brain. A candidate must resolve against
   MusicBrainz before it can be displayed. MusicBrainz supplies entity identity and
   release dates; LLM-proposed musical relationships remain `llm_inferred` with
   numeric confidence and must never be presented as verified facts.
2. **CSV files are the source of truth; `build/` and `exports/` are disposable.**
   Fix data problems in the CSVs and rebuild; never patch the DB directly.
3. **Controlled vocabulary only.** Descriptors must exist in `data/vocab.csv` before
   they are used in `data/descriptors.csv`. New terms require human approval.
4. **Provenance on everything.** Any new signal or reason added to API responses must
   carry a `source` label (curator | musicbrainz | wikidata | last_fm | llm_inferred) and a
   confidence value. A recommendation with an empty `reasons` list must never be
   returned (enforced in `app.py`; keep it enforced).
5. **Data rights lines:** MusicBrainz (CC0), Wikidata structured data (CC0), and
   human curation may be stored. Last.fm data is an optional query-time signal
   only, never written to the corpus.
   Do not add Spotify API, Apple Music API, or Rate Your Music data in any form.
6. **MusicBrainz etiquette:** max 1 request/second, descriptive User-Agent. Never
   parallelize MusicBrainz calls.
7. **Keep it one-person simple.** SQLite not Postgres, no Docker, no graph DB, no
   LangChain, no new frameworks, minimal dependencies (fastapi, uvicorn, requests,
   optional anthropic). If a change requires a new dependency, propose it and wait.
8. **LLM provenance boundary.** LLM calls may (a) map briefs onto the controlled
   vocabulary, (b) propose candidate entities for independent resolution, (c) infer
   recommendation fit using the brain engine's axes, and (d) compose prose over
   supplied evidence. They must not create verified facts. Query-time inferences are
   labeled `llm_inferred` and do not silently become curator data.

## Environment

- Windows 11, PowerShell, VS Code, Python 3.12. Use PowerShell syntax in instructions
  (`$env:VAR = "..."`, not `export`). Paths may contain spaces; quote them.
- Run commands from the repo root.
- Local secrets may be loaded from the ignored `.env` file into environment variables
  (`OPENAI_API_KEY`, `MUSICBRAINZ_CONTACT`, optional `LASTFM_API_KEY`). Never commit
  `.env`, expose keys to browser code, or place real credentials in `.env.example`.

## Commands

```powershell
pip install requests fastapi uvicorn            # base deps
python build_corpus.py resolve                  # verify seeds against MusicBrainz
python build_corpus.py expand --label "4AD" --bucket C
python build_corpus.py build                    # compile corpus.db + corpus.jsonl
python build_corpus.py stats                    # coverage report
uvicorn app:app --reload                        # run the platform
```

## Testing expectations

After any change to `app.py` or `build_corpus.py`, verify before declaring done:
- `python -m py_compile app.py build_corpus.py` passes.
- `GET /health` returns `ok: true` with a nonzero album count.
- A standard smoke request returns results where every result has ≥1 reason:
  `POST /recommendations` with brief "nocturnal elegant reverb-drenched",
  seed "The Cure", novelty "non_obvious".
- An impossible constraint (`year_min: 2030`) returns `coverage.status: "no_match"`,
  not fabricated results.
- A seed artist outside the corpus returns `known_outside_corpus` or `unknown`,
  never silent inclusion.

## Milestone protocol — announcing readiness

Work follows `plan.md` phase by phase. **Do not silently roll from one phase into the
next.** At the end of each phase, run that phase's exit-criteria checklist from
`plan.md` and report results to the human.

**Barebones-ready announcement (end of Phase 2):** when ALL exit criteria for
Phase 2 pass, the agent must post a clearly marked status message:

```
=== BAREBONES READY ===
Corpus: <N> albums (<N core>) across <N> buckets, <year-min>–<year-max>
Checklist: [pass/fail per Phase 2 exit criterion]
Known gaps: <list>
Awaiting human go-ahead for Phase 3.
```

…and then STOP. Phases 3+ start only on explicit human instruction. The same
announce-and-stop pattern applies at every subsequent phase gate.

## Style

- Python: standard library first; type hints on public functions; no premature
  abstraction. One file per concern (`build_corpus.py` = data, `app.py` = serving).
- Deterministic outputs: stable sort orders, seeded randomness only.
- Human-facing text in responses should be honest and specific, never padded.
- No em dashes in generated documents or copy.
